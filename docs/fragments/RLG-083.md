### RLG-083 — Every fragment tool defaults to the environment's store, from any working directory
- **RULED 2026-08-30T09:49:40-04:00** — A UNIT OF THIS PROJECT'S WORK WAS FILED IN THE ENVIRONMENT'S STORE, and the tool reported success.
`unit.py open` and `step.py run` were called from this project without `--store`, and both wrote
UNT-228 and EVD-339 to EVD-342 into `<env-root>/Environment/docs/fragments`. It was noticed at the
close, the work was re-run into this project's store as UNT-051 with EVD-048 to EVD-050, and that is
what was committed and pushed.

THE OWNER RULED ON THE CLEANUP, 2026-08-30: the strays are deleted rather than moved. Moving them
would have put two units in this store for one piece of work, because UNT-051 already holds the same
three passing runs from the re-run five minutes later. The only record without a counterpart was
EVD-339, an exit-127 from a bad interpreter path. The environment's store is byte-identical to its
last commit, its thread was restored with `git checkout`, all 711 of its fragments validate, and
nothing referenced the removed ids.

AND IT IS NOT CARELESSNESS THAT A REMINDER FIXES. `jurisdiction.resolve_root` in the shared commands
already implements the correct rule - it tests for a project's `docs/fragments` BEFORE the
environment's marker - and its docstring states this exact failure: "checking the environment marker
first would resolve every project to the environment's store and file a project's work in the wrong
place while reporting success."

Nothing on the default path calls it. `fragment.default_store()` returns the environment's path as a
constant; `step.py`, `thread.py`, `unit.py` and `maintenance.py` each define `default_store()` as a
call straight through to it, and `index.py` repeats the constant. So an omitted `--store` means "the
environment's store" in every tool, from every working directory, and `jurisdiction.home()` - the
function that answers it correctly - is asked by no CLI path.

THE JURISDICTION GATE CANNOT CATCH THIS, which is the part worth understanding. It fires when a
caller NAMES a foreign root without a note. Here the caller named nothing and was silently handed
someone else's store - which is the case `resolve_root` returns None to prevent, and which the
environment's own AUD-021 already ruled on: a silent redirect that reports success is worse than a
refusal, because the caller records that the work went where it asked.

WHAT THIS PROJECT DOES ABOUT IT, WHICH IS THE ONLY PART IN THIS PROJECT'S GIFT. Every call to
`fragment.py`, `unit.py`, `step.py` and `thread.py` from this project passes
`--store docs/fragments`, without exception and whether or not the tool is ever fixed. It is on the
thread as a constraint.

THE FIX ITSELF IS THE ENVIRONMENT'S TO MAKE. It is `default_store()` returning `jurisdiction.home()[1]`
in the six places above. It is not made from here: it is shared tooling that every project depends on,
and a visitor should not change what the shared commands mean. It is written up in the note left at
the environment root, where the next session there meets it on arrival.
