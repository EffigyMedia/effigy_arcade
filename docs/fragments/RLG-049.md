### RLG-049 — The police cars are won in the tournament, under pursuit
- **RULED 2026-08-28T17:47:58-04:00** — **Owner, 2026-08-28:** "I'd like to change the reward trigger for unlocking the cruiser and super
cruiser. Remove their previous triggers completely and change them to: if you win gold in the sports
tournament with hot pursuit turned on, you also unlock the cruiser. If you win gold in the supercar
tournament with hot pursuit turned on, you also unlock the super cruiser."

**Shipped in v0.9.6.**

**Removed, completely, as ruled.** Both police cars were earned on TEST DRIVE: the CRUISER for 20
miles on the clock under pursuit, the SUPERCRUISER for the same 20 miles at a 180mph average. Both
`if` blocks are gone. They were removed rather than left alongside the new triggers, because two ways
to win the same car is two things to keep working and two things to explain.

**Added.** In the tournament's final-round branch, beside the gold payouts that already exist:

    if(st === 1 && !optEasy && classOf(optBody) === 'sports')  -> cruiser
    if(st === 1 && !optEasy && classOf(optBody) === 'super')   -> supercruiser

`optEasy` is pursuit OFF, so `!optEasy` is the switch being on. There is no separate "sports
tournament" and "supercar tournament" in the code and none was added: the tournament already pays out
BY CLASS through `classOf(optBody)`, which is what the owner's two sentences describe. The gold and
the class rule stay exactly as they were - turning pursuit off still wins the formula car or the
paint, it simply does not win a police car.

**It also fixes a defect that was already there and would have been made worse.** The trophy screen
printed "FORMULA UNLOCKED" for EVERY gold and its button called `showUnlock('FORMULA')`. Gold has
paid out by class for some time: a sports ladder hands over the iridescent paint, and the screen has
been announcing an open-wheeler the player did not win. Adding a second prize would have made the
same screen wrong in a second way, so the prize is now computed - `goldNote`, `copCar`, `showCar` -
rather than asserted. A gold with pursuit off now says so, which is where the condition is most
discoverable: on the screen showing the result of not meeting it.

The unlock card's footnote is corrected with it. It read "20 MILES · ON THE CLOCK · UNDER PURSUIT"
for the CRUISER - the trigger that no longer exists - and said nothing at all for the SUPERCRUISER.
Each now names the ladder that pays it.

**Two variables were orphaned by the removal and were deleted rather than left.** `wonCruiser` was
set only by the removed blocks and read nowhere. `runSeconds` was accumulated every frame and its
only reader was the 180mph average. A comment at the accumulation site records where it went, so a
later session looking for a run timer finds out why there is not one instead of assuming there never
was.

**WHAT IS NOT VERIFIED, AND IT IS THE MAIN THING.** No harness can win a tournament: it is four races
of 10, 12, 16 and 24 miles, and there is no debug shortcut to a finish. So the branch this unit
exists to add has NOT been executed. What was verified is that nothing else broke - `node --check`,
`pack.sh --check` on all six gates, drive-test 23/23 across both driving games, smoke-test 6/6 - and
that is a different claim. A static parse of a branch is not evidence the branch is right, and this
project's own rule says so.

**The gap is tracked as [[RLG-050]]:** a debug jump to a tournament finish, which would make this and
every future reward change testable. Until then the acceptance test is the owner winning a gold with
pursuit on.
