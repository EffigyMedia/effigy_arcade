### RLG-063 — The arcade says which build it is running, and the commit says the same string
- **RULED 2026-08-29T04:05:33-04:00** — **Owner, 2026-08-29:**

> "We need a build identifier in your commit message that matches the same thing written into the
> dashboard of the arcade so I know I'm playing the right build for testing purposes."

**BUILT the same day, in v0.9.15.** The identifier is `Arcade.version` - there is no second number to
maintain, because every commit that changes the product already bumps it and every commit already
names it. What was missing is that **the arcade never printed it anywhere.**

Two places now show it, and both are places a tester is already looking:

- **the launcher's SETTINGS sheet**, as a BUILD row. It sits directly above FORCE UPDATE on purpose:
  "which build is this" and "give me the newest one" are the same question, and the answer to the
  first tells you whether you need the second.
- **every `.ark-opts` panel** - the pause menu and any title options screen, in every cabinet. It is
  printed even when a machine has no options at all, because a machine with nothing to configure is
  still a machine somebody is testing.

**IT ALSO CATCHES A STALE HALF, and that is the part worth keeping.** `sw.js` serves scripts
network-first with a short timeout and a cache fallback, so a slow connection can hand a device a
FRESH `arcade.js` beside a CACHED `road.js`, and nothing in the picture would say so - the arcade
would report the new build while running the old engine, which is the exact opposite of what this
fragment is for. So `road.js` stamps `window.ROAD_BUILD` with the version it was written for, and
`Arcade.buildTag()` reads `BUILD 0.9.15 / ROAD 0.9.14 - MIXED` when they disagree, in orange.

**That is the one case where a second copy of the version number earns its place.** The project's
standing rule is that a second copy is how two answers to one question begin. This is not that: each
file states which build IT came from, and the whole point is to detect the moment those differ.

**Proved rather than asserted:** the launcher sheet opens and its BUILD row reads `0.9.15` with a
non-zero bounding box; a cabinet's options panel prints `BUILD 0.9.15`; and forcing
`window.ROAD_BUILD = '0.0.1'` produces `BUILD 0.9.15 / ROAD 0.0.1 - MIXED`.

**The convention this places on every future commit:** a commit that changes anything the player
runs bumps `Arcade.version` AND `window.ROAD_BUILD` in the same commit, and names that version in
its subject line. A `chore:` commit that changes only records does not, and does not need to - there
is nothing new to test.
