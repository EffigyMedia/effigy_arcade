### RLG-003 — A pixel icon from the Effigy mark, and an honest loading counter
- **RULED 2026-08-28T09:40:33-04:00** — - **The icon was still Tiny Arcade's.** It is now built from the **Effigy Media symbol** - the three
  horizontal slats and three vertical slats - in the arcade's own palette on its own black, and
  pixelated. `tools/make-icon.py` generates both sizes and is committed, so the icon is reproducible
  rather than a binary nobody can regenerate.

- **The slats are uniform by construction, and the first attempt was not.** That version measured
  each bar out of `effigy.png` and rounded its four edges to the cell grid independently. Bars that
  differ by one pixel in the source - 52 against 53 - therefore landed on different cell counts, and
  the owner spotted the uneven slat immediately. **The mark is not six measured rectangles. It is
  one slat thickness and one gap, repeated:** width `6t + 5g`, height `3t + 2g`, the left block a
  square of side `3t + 2g`. Measured against the source that holds - `t` about 52.7 and `g` about
  16 gives 396 x 190 against the real 394 x 189. The generator now takes `t` and `g` and **cannot
  produce an uneven slat**.

- **The pixelation is structural, not a filter.** The art is composed one cell at a time on a small
  grid and blown up with `NEAREST`. A blur-and-posterize pass over a smooth render leaves half-lit
  edge pixels and reads as a resized photograph. Cell shading is a vertical ramp plus a
  **deterministic** dither - a hash of the coordinates, not an RNG - because an icon that differs
  between two builds shows up in every diff forever.

- **Sizes land on whole pixels.** 36 cells at 5 gives 180 exactly; 32 cells at 16 gives 512 exactly.
  Both use the same `t` and `g`, so they are one drawing at two resolutions.

- **THE CACHE GENERATION HAD TO BUMP, and this is the part that would have been missed.** `icon.png`
  is in `sw.js CORE_FILES`. Shipping a new icon under the same cache name means **every returning
  visitor keeps serving the old one out of cache, forever** - the change would have looked like it
  did nothing on exactly the devices that already had the site. Bumped v24 to v25.

- **The loading counter was reporting the wrong thing.** It counted files *checked*, not files
  *fetched*, so it climbed to 18/18 on every visit, warm or cold. Nothing was being downloaded -
  `cache.match` short-circuits each one - but a returning player watched what looked like a full
  download of the arcade every time. Measured on the live site before the fix: **cold 26 requests,
  warm reload 8.** The offline layer was working the whole time; only the display lied. The panel
  now says `READY - OFFLINE` when nothing was pulled, and names the count when something was.

- **`fonts/LICENSES.md` was being precached.** The generator globbed `fonts/*` rather than
  `fonts/*.woff2`, so a document no running game asks for was fetched on every first visit. Assets
  went from 18 to 17.

- **One defect found and NOT fixed here, because it needs its own unit.** `pack.sh` validates that
  `sw.js` and `assets.js` agree on the cache name **before** it regenerates `assets.js`. A
  legitimate version bump therefore deadlocks the build - the gate refuses, and the only way past is
  to hand-edit the generated file. `assets.js` was seeded by hand this once to get through. The
  ordering is wrong and the fix is to regenerate first, then verify.

- **Proof.** `./pack.sh` all gates, 38 files, 688KB. `smoke-test` 5/5.
