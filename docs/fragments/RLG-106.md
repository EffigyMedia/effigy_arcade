### RLG-106 — The time reward does not say what it is a reward of
- **RULED 2026-08-31T10:50:58-04:00** — Owner, 2026-08-31: "When you're rewarded more time, it just has a number '+20', it should be '+20
sec'."

IT IS ONE STRING AND THE FIX IS TRIVIAL. `flashWarn('CHECKPOINT  +' + CLOCK_BONUS)` at the checkpoint
hit. The number has no unit, so it reads as points, or a multiplier, or a place - anything but
seconds, which is the one thing it is.

THE REASON IT MATTERS IS THAT IT IS THE ONLY PLACE THE CLOCK IS EVER ADDED TO. Everything else about
the timer counts DOWN in the HUD where the unit is established by context. This is the single moment
a number goes up, it appears in a flash that is gone in a second, and it is the number the whole
Interstate is played against.

TAKE THE UNIT FROM ONE PLACE. `CLOCK_BONUS` is the value; whatever is written next to it should not
be a second literal that can drift out of step with the HUD's own wording. Read what the timer calls
itself and match it, so the flash and the dial agree.

AND IT IS THE SAME QUESTION [[RLG-100]] IS ABOUT. The owner has separately reported that the sports
car barely makes a checkpoint at full speed, which is a statement about this same `CLOCK_BONUS`
against the distance between boards. The wording fix is independent and should not wait for it - but
whoever changes the number should check this string still reads correctly if the award ever becomes
per-class.
- **RULED 2026-08-31T17:24:00-04:00** — BUILT in v0.10.32. The checkpoint flash reads `CHECKPOINT  +20 SEC`.

AND THE UNIT ALREADY EXISTED, SPELT DIFFERENTLY, which this ruling could not have known without looking. There are exactly two moments that change the clock and they disagreed about what a clock is measured in: the wreck penalty read `-2s` and the checkpoint read `+20`. One used a lowercase abbreviation and the other said nothing at all. Both are built by `timeFlash(label, secs)` now, from one `CLOCK_UNIT`, so they cannot drift apart again - which is exactly what this ruling asked for when it said to read what the timer calls itself rather than write a second literal.

THE PENALTY'S NUMBER WAS A LITERAL TOO, and that is the same fault one step further on. The `2` in `-2s` was written into the string while the value it describes is the wreck penalty itself, so changing the penalty would have left the text announcing the old one. That value is `WRECK_SECS` now and both flashes take their number from the value rather than from beside it.

THE HUD HAS NO UNIT TO TAKE. Worth recording, because this ruling said to read what the timer calls itself: the HUD's clock is `<span>TIME</span><b>60</b>` - a LABEL and a bare number, with no unit anywhere. So there was nothing to inherit and the word had to be chosen. It is the owner's own: `SEC`.

PROVED, AND THE PROOF CROSSES ONE. `tools/race-test.py` is the checkpoint harness and it already proved boards are PLACED - which is not the same as crossing one, and only a crossing produces the flash. It drives on at top speed until the flash fires, reads `#warn`, and asserts the text carries a number AND a unit word. Measured: `CHECKPOINT  +20 SEC`, awarding 20 SEC. Putting the bare string back by hand fails it with the exact old text.

STILL OPEN AND NOT THIS RULING'S: [[RLG-100]], the sports car barely making a checkpoint at full speed, which is a statement about `CLOCK_BONUS` against the distance between boards. This ruling warned that whoever changes that number should check the string still reads correctly if the award ever becomes per-class - and it now does, because the string is built from the value rather than containing a copy of it.
