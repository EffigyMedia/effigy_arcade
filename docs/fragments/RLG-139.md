### RLG-139 — The engine's build stamp went stale for 22 versions and nothing caught it
- **RULED 2026-09-01T08:39:56-04:00** — FOUND WHILE SHIPPING v0.11.5, and it was found by reading rather than by any check.

WHAT IT IS FOR. The service worker serves scripts network-first with a cache fallback, so a
device can end up with a fresh shell beside a cached engine - which is the fault that once
black-screened the game, and which was fixed at 0.10.12 by bumping the cache names. To make
that state visible, each file states which build it came from: `Arcade.version` in
`arcade.js`, and `window.ROAD_BUILD` in `road.js`. `Arcade.buildTag()` compares them and
says MIXED when they disagree, and the BUILD row in SETTINGS shows the result.

THE COMPARISON HAS BEEN TRUE ON EVERY BUILD SINCE 0.9.15. `ROAD_BUILD` was last touched in
the commit that introduced it and sat at 0.10.37 while the shell moved to 0.11.4 - so the
tag has been reading MIXED for twenty-two versions, on a correctly served build, with
nothing mixed about it.

AND THAT IS WORSE THAN THE STAMP BEING ABSENT. An instrument that is always alarming is an
instrument nobody reads, so on the day the cache really does go half-updated the BUILD row
will say exactly what it has been saying all along. This is the same failure the project has
already recorded twice in other words: a check that cannot go green teaches the reader to
stop looking, and a check that cannot go red measures nothing.

THE STAMP IS BUMPED TO 0.11.5 IN THAT SAME COMMIT, because the note beside it says to bump it
with the version every time. THAT IS NOT THE FIX. The fix is that nothing should be able to
forget it again: two numbers that must agree, kept by hand in two files, will drift a second
time. Either the packer asserts they agree - it already regenerates and validates, and it
has a whitelist of what is shipping - or `smoke-test.py` reads `Arcade.buildTag()` and fails
on MIXED, which has the advantage of testing the thing the player would see rather than the
two strings behind it.

NOT DECIDED HERE, and the owner may prefer a third answer: derive the engine's stamp from
the shell at load rather than typing it twice. That would delete the drift and also delete
the check, because two copies is the whole mechanism - the point is that each FILE says
where it came from, and a value read from the other file cannot say that.
