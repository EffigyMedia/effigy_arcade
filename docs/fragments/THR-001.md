**Constraints in force**
- Tiny Arcade is a SEPARATE repository and is never touched from here. It is parked, complete and still playable at effigymedia.github.io/tiny_arcade
- never edit this product through the GitHub web UI - an upload replaces a whole file, so there is no merge and no conflict. Six shipped fixes were reverted that way in the parent, behind a green build
- keep pack.sh --standalone working. It emits one self-contained HTML file per machine, and that is the exit route when a game is split into its own binary wrapper
- commits are authored as the project owner - no AI identity, no co-author trailer. One unit, one commit, committed immediately
- MOBILE ONLY - touch is the input. Keyboard, mouse and gamepad are out of scope (owner ruling 2026-08-25, RLG-002). The inherited Arcade.menu and A.pad layers stay for now but are not load-bearing; do not extend them
- road.js is BOTH driving games - a fix there ships to Interstate and Motorsport unless CFG.circuitOnly gates it. drive-test covers both for exactly that reason, and circuit-test asserts what a circuit must NOT have
- PROVE IT, and check the proof is not vacuous. Four guards in this list passed with the bug present before they were fixed - the traffic boolean, the rev limiter three times over. Reintroduce the defect and watch the check fail before believing it
- ONE PHYSICS FOR EVERY CAR (owner, 2026-08-28). The rubber band is the ONLY named exception. NPCs never get better cars than the player - a rival is competitive because it DRIVES well, which is why RLG-033 is load-bearing rather than polish
- The car is CAPABLE, the driver DECIDES. This shape recurs in three separate owner rulings - traffic stats vs drivers (RLG-042), indicators wired but untriggered (RLG-052), personalities (RLG-054). Never write a branch that names a vehicle class to get one of them
