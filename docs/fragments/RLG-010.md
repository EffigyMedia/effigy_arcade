### RLG-010 — Every machine owns everything it stores: Arcade.scope
- **RULED 2026-08-28T12:15:29-04:00** — - **The requirement, from the owner.** These four are standalone games that share a launcher only
  while they are built. **Anything they share in storage is a thing that breaks, or silently goes
  missing, on the day one of them is split out.**

- **Three stores were shared, and one of them made the last unit's claim false.**

  | Store | Was | Now |
  |---|---|---|
  | the shell's options | `effigyarcade.opts.v1.<TITLE slug>` | `effigyarcade.<id>.opts.v1` |
  | audio settings | `effigyarcade.audio.v1` - one set for all four | `effigyarcade.<id>.audio.v1` |
  | intros already seen | `effigyarcade.cinema.v1` - one blob for all four | `effigyarcade.<id>.cinema.v1` |

- **The options key was the worst of the three, for two reasons at once.** It was keyed on a slug of
  the cabinet's **title**, which is display text - so renaming Highway to Redline Interstate silently
  orphaned every option a player had set, because the key moved with the words. And that shape
  matched none of the patterns `Arcade.save.clear` recognizes, **so the erase shipped in [[RLG-007]]
  and [[RLG-008]] left the shell's own settings behind while reporting it had cleared everything.**
  That claim is corrected here rather than left standing.

- **`Arcade.scope` is the mechanism**, and it is defined in `audio.js` rather than the shell because
  `audio.js` loads first and needs it immediately. It reads `<meta name="arcade-id">`, falls back to
  the file name for a standalone build that was renamed, and falls back to `launcher` for
  `index.html`. Each cabinet now carries that meta tag explicitly.

- **The payoff is that the namespace rule does the work.** Every one of these keys is now
  `effigyarcade.<id>.something`, which `ownedBy` already recognized, so **the prune the cinema needed
  is deleted rather than extended**. Nothing about one machine is stored anywhere that erasing it
  cannot reach.

- **The launcher seeds a cabinet once, and the seed is WRITTEN DOWN.** Splitting the audio store
  would otherwise cost a real convenience - turning the music down in the launcher and having a
  cabinet ignore you. A machine with no settings copies the launcher's on first visit. **The first
  attempt only read the seed and never persisted it**, which meant the cabinet was not owning
  anything - it was re-reading the launcher on every load, and a later change there would have moved
  it again. Persisting on first visit is what makes "its own settings" true rather than a
  description of what happens until somebody touches a slider. Caught by the isolation probe, not by
  reasoning.

- **Proven.** The `saves()` check in `smoke-test.py` now seeds **all six shapes** a machine can own,
  plus a prefix-sharing neighbour, plus the launcher scope, and asserts: none of the six survive an
  erase, the neighbour and its audio settings do survive, and clearing `launcher` removes nothing
  because it is reserved. `tools/isolation-test.py` is kept as a tool and proves the other half:
  every cabinet resolves its own scope, each is seeded from the launcher once, and changing one
  machine's volume leaves the others where they were - measured, quietus vMaster 0.1 against
  hardpoint vMaster 0.5.

- **The rule is in the brief**, with the instruction that a new store must be added to the `saves()`
  check. That check exists so this cannot rot quietly.
