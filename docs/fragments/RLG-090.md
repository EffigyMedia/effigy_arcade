### RLG-090 — A retry starts a new run, not the last one continued
- **RULED 2026-08-30T20:31:17-04:00** — Owner, 2026-08-30: on a time-over, hitting RETRY carries state over into the new run - the example given is starting in a dry biome with snow slipperiness still applied.

THAT IS TWO PIECES OF STATE THAT DISAGREE, WHICH IS WORSE THAN EITHER BEING WRONG. The place is fresh and the grip is not, so the road looks like one thing and drives like another, and nothing on screen explains why the car will not hold a line.

THE SHAPE IS THE SAME ONE RLG-022 JUST HAD. The biome countdown and the flag that says a run has chosen its opening place were both left uncleared at a reset, so a second run inherited the first one's map; they are cleared now. Settled snow, wetness and whatever else the weather leaves behind are the same class of thing and were not part of that unit. Check whether the retry path even reaches reset(), or whether it is a separate route that was written before reset() carried this much.

AND THE FIX SHOULD BE A LIST OF WHAT A RUN OWNS, not another line added to reset(). Two of these have now been found one after the other, which says the failure is that nobody can see at a glance what a run is supposed to start with. Whatever is written down has to be checkable, or the third one arrives the same way.
