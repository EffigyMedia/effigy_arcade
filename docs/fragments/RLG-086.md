### RLG-086 — The garage answers a tap at once, not half a second later
- **RULED 2026-08-30T19:35:39-04:00** — Owner, 2026-08-30, from the device: on the title menu, choosing a new colour takes about half a second before the selection changes, and toggling is the same. The owner's own reading: the stripes were changing the vehicle, so it is probably having to rebuild the rendered car.

THE READING IS ALMOST CERTAINLY RIGHT AND IT SHOULD STILL BE MEASURED. setBody already calls buildSprites, which rebuilds every sprite in the game rather than the one car whose paint changed, and a colour or a stripe is exactly the kind of change that would be routed through it. That is a hypothesis with an obvious shape and this project has been wrong about obvious shapes before - the traffic stat table read TRUE while three comments around it were false. Time the handler before changing it.

HALF A SECOND IS NOT A RENDER PROBLEM, IT IS A WORK PROBLEM. Nothing in a menu should take that long to paint. Either the rebuild is doing far more than the one car needs, or it is being done on the tap rather than being deferred, and those have different fixes: build one car's sprites instead of all of them, or paint the new colour immediately and rebuild behind it. The first is better if it is fast enough, because the second leaves a frame where the car and the swatch disagree.

AND IT IS A TOUCH TARGET, WHICH RAISES THE BAR. A control that answers half a second after a thumb lifts reads as a control that did not register the tap, so the player taps again. That is the actual cost of this, rather than the half second itself.
